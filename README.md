# MaintainIQ — ML-Based Predictive Maintenance System

A machine learning system to predict industrial equipment failure risk using milling machine sensor telemetry from the UCI AI4I 2020 dataset.

---

## 📖 Project Overview & Key Features

Unplanned machine breakdown in industrial manufacturing leads to costly downtime, production bottlenecks, and secondary hardware damage. **MaintainIQ** applies machine learning to operational sensor telemetry (temperatures, rotational velocity, torque, and tool wear) to estimate failure likelihood before catastrophic stops occur.

### Key Capabilities
- **Leakage-Safe Preprocessing Pipeline**: Fitted exclusively on training data using a reproducible 80/20 stratified split (`random_state=42`). Categorical features (`Type`) are one-hot encoded and numerical features are scaled without test data contamination.
- **Multi-Model Benchmark**: Trains and evaluates four classifiers with tailored class-imbalance mitigation:
  - **Logistic Regression** (Linear baseline with inverse-frequency class weights)
  - **Random Forest** (Bootstrap ensemble with balanced subsampling)
  - **XGBoost** (Gradient-boosted decision trees with training-derived `scale_pos_weight`)
  - **CatBoost** (Gradient boosting with automated inverse-frequency balancing)
- **Single Machine Risk Scoring**: Interactive UI allowing real-time telemetry inputs with model-based risk bands for operational guidance (not guaranteed maintenance decisions):
  - **Low Risk** (probability < 30%): Model predicts nominal operating state
  - **Medium Risk** (probability >= 30% and < 70%): Elevated risk band indicating inspection recommended
  - **High Risk** (probability >= 70%): Critical risk band indicating high probability of equipment failure
- **CSV Batch Telemetry Evaluation**: Batch processing with strict schema validation, automatic exclusion of non-feature/leakage columns, failure probability scoring, and summary health diagnostics.
- **Model Explainability & XAI**:
  - Global Permutation Feature Importance evaluating drop in PR-AUC over 10 repeats on the test split.
  - Local instance attributions powered by TreeSHAP for individual prediction transparency.
- **Interactive Streamlit Dashboard**: Multi-tab user interface for system overview, inference, batch analysis, classifier benchmarking, and explainability.

## 🔬 Dataset & Real-World Limitations

### Dataset Description
- **Source**: [UCI Machine Learning Repository: AI4I 2020 Predictive Maintenance Dataset](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset) (ID: 601, Matzka, 2020).
- **Scale**: 10,000 records, 14 attributes.
- **Class Imbalance**: ~3.39% failure incidence (339 failure records out of 10,000).

### Six Approved Model Features
1. `Type`: Product quality variant (`L`: Low 50%, `M`: Medium 30%, `H`: High 20%).
2. `Air temperature [K]`: Ambient room temperature (generated around 300 K).
3. `Process temperature [K]`: Cutting process heat (generated around 310 K).
4. `Rotational speed [rpm]`: Spindle speed calculated from motor power and torque.
5. `Torque [Nm]`: Resistance torque normally distributed around 40 Nm.
6. `Tool wear [min]`: Cumulative tool contact time during cutting operations.

### Target & Monitored Failure Modes
- `Machine failure`: Binary target (`0` = Normal, `1` = Failure).
- Monitored modes: Tool Wear Failure (`TWF`), Heat Dissipation Failure (`HDF`), Power Failure (`PWF`), Overstrain Failure (`OSF`), and Random Failure (`RNF`).

> [!WARNING]
> **Synthetic Dataset Disclosure & Real-World Limitations**
> The UCI AI4I 2020 dataset was generated by a phenomenological physical simulator reflecting milling machine dynamics. MaintainIQ is built for academic and educational demonstration.
> 
> Statistical associations and feature importances learned by the models reflect empirical dependencies within the simulated dataset. They **do not** establish physical causation and **cannot** be interpreted as verified real-world mechanical reliability guarantees without validation on actual factory-floor telemetry.

## 📈 Model Comparison & Imbalance Metrics

In industrial predictive maintenance, failures represent only ~3.39% of operating time. Under extreme class imbalance:
- **Accuracy is Deceptive**: A naive model predicting "No Failure" 100% of the time achieves **96.61% accuracy**, but fails to prevent a single breakdown.
- **Recall ($TP / (TP + FN)$)**: Measures the proportion of actual failures caught. High recall avoids catastrophic unplanned downtime.
- **Precision ($TP / (TP + FP)$)**: Measures the proportion of failure alarms that are genuine. High precision prevents unnecessary and expensive maintenance halts.
- **F1-Score**: The harmonic mean of Precision and Recall, balancing false alarms against missed breakdowns.
- **PR-AUC (Precision-Recall Area Under Curve)**: The primary metric for model selection. Unlike ROC-AUC (which can look artificially high due to thousands of true negatives), PR-AUC specifically evaluates the trade-off between precision and recall across all classification thresholds on the minority positive class.

### Benchmark Results on Held-Out Test Set (2,000 samples, 68 failures)

| Model | PR-AUC | F1-Score | Precision | Recall | ROC-AUC | Imbalance Strategy |
|---|:---:|:---:|:---:|:---:|:---:|---|
| **XGBoost** (Selected) | **0.8283** | **0.7376** | 0.7123 | 0.7647 | 0.9651 | `scale_pos_weight = n_neg / n_pos` (~28.52) |
| **Random Forest** | 0.7368 | 0.7132 | **0.7541** | 0.6765 | 0.9574 | `class_weight='balanced'` |
| **CatBoost** | 0.7068 | 0.5133 | 0.3671 | **0.8529** | **0.9702** | `auto_class_weights='Balanced'` |
| **Logistic Regression** | 0.3818 | 0.2419 | 0.1418 | 0.8235 | 0.9070 | `class_weight='balanced'` |

## 🛠️ Prerequisites & Setup Guide

### 1. Prerequisites (macOS & Python 3.12)
- macOS (Apple Silicon M-series or Intel)
- Python 3.12 installed. Check your version:
  ```bash
  python3 --version
  ```
  If Python 3.12 is not installed, install it using Homebrew:
  ```bash
  brew install python@3.12
  ```

### 2. Create and Activate Virtual Environment
From the repository root:
```bash
python3.12 -m venv .venv
source .venv/bin/activate
```

### 3. Install Dependencies
```bash
pip install --upgrade pip
pip install -r requirements.txt
```

## 🚀 Execution Workflow (Step-by-Step)

Follow these steps on a fresh clone to download data, train models, generate explainability reports, run tests, and launch the application.

### Step 1: Download the Official Dataset
Downloads and validates the official UCI AI4I 2020 dataset archive into `data/raw/ai4i2020.csv`:
```bash
python scripts/download_data.py
```

### Step 2: Train Models & Generate Benchmarks
Performs a stratified 80/20 train/test split, trains Logistic Regression, Random Forest, XGBoost, and CatBoost, evaluates test metrics, saves comparison reports to `reports/tables/`, and exports the best pipeline to `models/model.joblib`:
```bash
python -m src.train
```

### Step 3: Generate Explainability Reports & Figures
Computes permutation feature importance (PR-AUC metric drop) over 10 repeats, saves the summary figure to `reports/figures/feature_importance.png`, and writes importance tables to `reports/tables/`:
```bash
python -m src.explain
```

### Step 4: Run the Complete Test Suite
Runs all 66 unit and integration tests with verbose reporting:
```bash
python -m pytest tests/ -v
```

### Step 5: Launch the Streamlit Dashboard
Starts the interactive web application:
```bash
streamlit run app.py
```
Open your browser and navigate to: **`http://localhost:8501`**

### Troubleshooting
- **Model artifact missing warning in Streamlit (`⚠️ Model artifact not found at models/model.joblib`)**:
  Run `python -m src.train` in your activated virtual environment to train the models and generate the artifact.
- **Feature importance chart or table missing**:
  Run `python -m src.explain` to generate `reports/figures/feature_importance.png` and `reports/tables/feature_importance.csv`.
- **Dataset not found (`data/raw/ai4i2020.csv`)**:
  Run `python scripts/download_data.py` to fetch and validate the dataset from the UCI archive.
- **Port already in use (`Port 8501 is already in use`)**:
  Launch Streamlit on an alternative port:
  ```bash
  streamlit run app.py --server.port 8502
  ```
